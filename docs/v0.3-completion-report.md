## Deviations from DESIGN.md

1. **`qgis_load_layer(crs=...)` override deferred to v0.4.** When the caller
   passes a non-`None` `crs` argument, the tool raises `NotImplementedError`
   pointing to `qgis_eval` as the v0.3 escape hatch. Reason: the plugin already
   has a `set_layer_crs` command, but wiring + testing the post-load CRS
   override added scope without v0.3-demo value (the test data — `polbnda_jpn_new.shp` — has a valid `.prj`).
   The simple no-`crs` path (the common case) is fully implemented.

2. **`qgis_figures_to_pptx` layouts `two_column` and `title_image_caption`
   degrade to `title_only`.** v0.3 ships `title_and_image` and `image_only`
   with full fidelity; the other two are accepted but render as
   `title_and_image`. Promoting them to distinct layouts is mechanical and can
   land in any later release. The Pydantic enum still admits all four.

3. **Memory-layer-rebuild architecture for `qgis_render_choropleth` is
   plugin-side, not MCP-side.** The original "approach B" plan called for the
   MCP server to read the CSV with stdlib `csv`, build the dict, and ship it
   to the plugin — that part is unchanged. What moved server-side is the
   geometry-copy step: the plugin's `get_layer_features` returns geometry as
   a *summary* (`"Polygon with N points"`) for token efficiency, not full
   WKT. So copying 47–110 polygon geometries through the socket would have
   either required extending `get_layer_features` with a `full_wkt=True`
   flag or marshalling 100s of KB of WKT per render. The chosen path — one
   plugin command that does load + memory-build + style + render + cleanup
   — keeps the join key/value parsing on the MCP side and the geometry
   inside QGIS, satisfying the design intent (no zones-layer mutation, clean
   `n_matched`/`n_unmatched` accounting, hard-fail on zero matches) without
   the geometry round-trip.

## Proposed scope for v0.4

Ship the headless transport. Concretely: `executors/headless.py` running a
long-lived Python subprocess that initialises `QgsApplication` with
`QT_QPA_PLATFORM=offscreen`, serving the same dispatch surface as
`PluginExecutor`. Add `--transport={plugin,headless,auto}` CLI selection (auto
probes port 9877, falls back to headless). Re-run every v0.3 unit test
parametrized over both executors to prove the seam is real. Wire the plugin's
existing `set_layer_crs` command through `qgis_load_layer(crs=...)` — that
clears the only DESIGN-doc deviation in the v0.3 tool surface. Build
`scripts/build_mfs_zones.py` so that v0.4 gains a real MFS-coded polygon
layer (`assets/zones_mfs.gpkg`) and `qgis_render_choropleth` can be tested
against `zone_trips.csv` directly, not the prefecture-aggregation workaround.
