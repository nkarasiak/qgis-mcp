transport (headless transport is v0.4, do *not* implement it here).

  implementation plan as a short comment block at the top of the function
  before the body, then implement. If your plan disagrees with
  `DESIGN.md`, update the doc first.

  someone will need this" parameters. If you find yourself adding generality,
  delete it.
- **No new dependencies** beyond what's already in `pyproject.toml` plus
  `python-pptx` (already declared as the `pptx` optional extra). If you

- **Errors must be actionable.** Every raise must include a suggested next
  tool call (e.g., `LayerNotFoundError("path X not found — try
  qgis_layer_inspect first")`). See `DESIGN.md` §5.
- **Output paths are absolute.** No relative paths in any response.
- **Do not delete `_archive/`.** It's reference material.
- **PPTX template:** there is no Sekimoto-lab default template; ship with
  a generic blank deck. (The user explicitly answered "no" to a default

## Workflow

1. Use **TaskCreate** to lay out the v0.3 work as 6–10 concrete tasks before
   touching code. Mark in_progress / completed as you go.
2. **Plan first**, especially for `qgis_render_choropleth` — it's the most
   complex tool because of the optional CSV join. Write the algorithm out
   before coding. Consider edge cases: missing join key, mismatched zone IDs,
   non-numeric value column, n_features < n_classes.
3. **Implement bottom-up**. Order:
   1. `qgis_layer_inspect` (no plugin needed — pure metadata read; can run
      headless via `osgeo` if available, else via plugin's `get_layer_info`).
   2. `qgis_load_layer` (wraps plugin's `add_vector_layer` /
      `add_raster_layer`).
   3. `qgis_render_map` (wraps plugin's `render_map`).
   4. `qgis_render_choropleth` (orchestrates load + style + render +
      optional join).
   5. `qgis_figures_to_pptx` (independent — uses python-pptx, no plugin).
4. **Test each tool** as you implement, against the real PFLOW data. Don't
   batch tests at the end. The plugin needs to be installed and QGIS open
   for tools 2–4; you can install via `python install.py --clients
   claude-desktop` from the repo root, then enable the plugin in QGIS
   (`Plugins > Manage and Install > QGIS MCP North`).
5. **Stop and ask** before doing any of: changing tool names, dropping a
   tool from the v0.3 list, adding a new tool not in the design doc,
   modifying response field names, adding a new dependency, or starting
   on v0.4 work.
6. **Update `docs/DESIGN.md`** as you discover anything that contradicts
   it. Note discoveries in `docs/DESIGN.md` §8 (open / resolved questions)
   so the next session has the latest reality.
